Three patterns to know

What the audit found at pattern level.

Three umbrellas that account for nearly every finding below. The catalog of 54 individual findings is the inventory; these are the shapes the inventory takes.

A1
Theme CC · Controls Coordinate

Controls don't coordinate with each other

Each control acts alone. Template changes don't update Field name. Format locks. Translation's Property picker gets stuck.

Why it matters

Header type picker handles form coordination correctly. Template dropdown doesn't. Format dropdown loses its binding after template switches. Translation's Property picker stops accepting new custom field selections. Users hit three different "stuck" moments in one sitting, with no error messaging to explain any of them.

Suggestion

Treat the panel as one coordinated form. All controls bind to a single form model. Template change cascades to Field name (unless user-edited), Format, Property, Language — each resets to the new template's default.

Findings

  • CC2 — Field name doesn't update when Template changes
  • CC3 — Format dropdown locks after two template switches
  • CC4 — Translation Property picker gets stuck
  • CC5 — Template change strands the dropdown options list
A2
Theme CS · Path-driven divergence

Form doesn't coordinate with the path

Same entry point, same template, different form depending on path. Two users get different AI output from what should be the same configuration.

Why it matters

manual→fillwithAI shows the Fill method switcher and defaults Progress Updates to "Today." AI-direct hides the switcher and defaults to "Last 24 hours." Different AI output from what should be the same configuration. The path (where the user came from) is silently carrying form state.

Suggestion

Path shouldn't determine form state. Fill method renders everywhere. Progress Updates defaults to "Last 24 hours" on every path. Defaults bind to template, not to entry point.

Findings

  • CS14 — Fill method switcher missing on AI-direct
  • CS16 — Progress Updates default splits on path
A3
Theme CS · Cross-entry-point divergence

Same form looks different depending on entry

Three entry points (View / Task / CFM), three layouts, three capability sets. CFM — the admin flow — has fewer controls than View.

Why it matters

View gets full permissions. Task has no Settings section at all. CFM shows Pinned + Visible-to-Guests only. Same form, three execution paths. Workspace admins using CFM — the most senior users — have the fewest controls.

Suggestion

One component, three contexts. Variants differ in width and density, not in controls. Full Settings + Permissions render everywhere; the admin flow gets the same field-level controls a team member gets in View.

Findings

  • CS15 — Permissions are View-only
  • CS2 — Description treatment differs across variants
  • CS4 — Eight Settings Screen controls treated differently across variants
  • CS5 — CFM uses two-column layout while others single-column
